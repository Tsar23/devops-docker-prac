## 1. Мета роботи
[cite_start]Навчитися налаштовувати CI/CD сервер Jenkins для автоматизованого розгортання (деплою) коду з системи контролю версій GitHub у цільове середовище[cite: 664, 665].

## 2. Інструментарій
* **Система CI/CD:** Jenkins
* **Контроль версій:** GitHub
* [cite_start]**Тип збірки:** Freestyle project [cite: 671]

---

## 3. Алгоритм налаштування автоматичного пайплайну

Для реалізації безперервної доставки (CD) було спроєктовано наступний робочий потік:

### 3.1. Ініціалізація проєкту в Jenkins
[cite_start]У веб-інтерфейсі Jenkins було створено новий проєкт типу **"Freestyle project"**[cite: 670, 671]. [cite_start]У розділі "Source Code Management" обрано Git та вказано URL поточного GitHub-репозиторію (`https://github.com/Tsar23/devops-docker-prac.git`) для підключення джерела коду[cite: 673, 674].

### 3.2. Налаштування тригера збірки (Build Trigger)
[cite_start]Для того, щоб система автоматично реагувала на зміни в коді, у розділі "Build Triggers" активовано опцію **"GitHub hook trigger for GITScm polling"**[cite: 676]. [cite_start]Це дозволяє Jenkins ініціювати процес розгортання одразу після отримання push-коміту[cite: 677].

### 3.3. Налаштування кроку збірки (Build Step)
[cite_start]Як інструмент виконання розгортання використано крок **"Execute shell"**[cite: 678, 679]. У цьому блоці прописується виклик скрипта `deploy.sh` (представлений у репозиторії), який виконує зупинку старого сервісу, підтягування нового коду та перезапуск додатка.

### 3.4. Конфігурація Webhook на стороні GitHub
[cite_start]Для забезпечення двостороннього зв'язку, в налаштуваннях репозиторію на GitHub (Settings -> Webhooks -> Add webhook) додано адресу сервера Jenkins[cite: 687, 689].
* [cite_start]**Payload URL:** `http://<Jenkins-IP>:8080/github-webhook/` [cite: 690, 694]
* [cite_start]**Контент:** Налаштовано спрацьовування виключно на "Just the push event"[cite: 694].

## 4. Висновок
[cite_start]В ході виконання практичної роботи було детально опрацьовано процес налаштування сервера Jenkins для автоматизації етапу Continuous Deployment[cite: 696]. Конфігурація Webhooks у поєднанні зі скриптами розгортання усуває необхідність ручного втручання в процес деплою. [cite_start]Використання зв'язки GitHub + Jenkins гарантує, що кожна нова версія коду, яка потрапляє в головну гілку, буде миттєво та безпечно доставлена на сервер, що значно підвищує ефективність життєвого циклу розробки[cite: 697, 698].
