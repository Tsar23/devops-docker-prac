## 2. Оцінка існуючої культури та процесів
* [cite_start]**Збір інформації:** Проведено серію інтерв'ю з розробниками Python-бекенду, тестувальниками та керівниками проєкту для розуміння поточних процесів [cite: 898-905]. [cite_start]Проаналізовано існуючий інструментарій (робота у VS Code, локальне тестування)[cite: 906].
* [cite_start]**Виявлені виклики:** Визначено головні "болючі точки": довгі цикли розгортання оновлень, періодичні помилки під час ручного деплою у продакшені та недоліки в комунікації між учасниками розробки [cite: 907-910].

## 3. Визначення цілей та вимог
* [cite_start]**Бізнес-цілі:** Скорочення часу до ринку нових фіч системи, підвищення якості продукту та зниження вартості експлуатації серверних потужностей [cite: 913-915].
* [cite_start]**Технічні вимоги:** Автоматизація тестування коду, впровадження неперервної інтеграції та доставки (CI/CD) через GitHub Actions, а також налаштування моніторингу у реальному часі[cite: 917].

## 4. План впровадження
### 4.1. Стратегія та Роудмап
* [cite_start]**Короткострокові цілі (3-6 місяців):** Вибір та налаштування базових інструментів (Docker, GitHub Actions, базовий моніторинг) та проведення стартових тренінгів для команди [cite: 920-921].
* [cite_start]**Довгострокові цілі (1-2 роки):** Повний перехід на управління інфраструктурою як кодом (IaC) за допомогою Terraform та Ansible, впровадження просунутих метрик [cite: 920-921].

### 4.2. Комунікаційний план
[cite_start]Розроблено план комунікації для залучення всіх учасників[cite: 923]. [cite_start]Синхронізація розробників та операційних інженерів відбуватиметься через регулярні зустрічі та щотижневі звіти про прогрес у робочому просторі "UniSuper Star"[cite: 924].

### 4.3. Планування змін у культурі
[cite_start]Сплановано ініціативи для розвитку відкритості та співпраці: спільні сесії code review, командоутворюючі заходи та періодична ротація членів команди між різними модулями проєкту [cite: 927-929].
